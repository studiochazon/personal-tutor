# Personal Tutor AI - Development Rules

This directory contains the development rules and guidelines for the Personal Tutor AI project. These rules are automatically applied by Cursor IDE to ensure consistent development practices.

## Rules Structure

### `style.md`
**UI/UX Design System** - The single source of truth for all visual design decisions including:
- Color palette and semantic colors
- Typography scale and font families
- Spacing system and layout guidelines
- Component patterns and CSS implementations
- Accessibility requirements
- Responsive design breakpoints

### `ui-development.md`
**UI/UX Development Guidelines** - Rules for frontend development including:
- Style guide compliance requirements
- SvelteKit-specific guidelines
- Component structure and organization
- State management best practices
- Development workflow

### `general-development.md`
**General Development Rules** - Core development practices including:
- Tech stack specifications (SvelteKit, TypeScript, MySQL, OpenAI)
- Code style and organization
- Database and API design
- Security best practices
- Testing and performance guidelines
- Environment and deployment procedures

### `ai-development.md`
**AI/LLM Development Rules** - Specific guidelines for AI integration including:
- Course generation guidelines and system prompt compliance
- OpenAI API integration best practices
- Video integration and content management
- Error handling and monitoring
- Performance optimization and caching
- Security and privacy considerations
- Testing and quality assurance

## Usage

These rules are automatically applied by Cursor IDE when working on the project. They ensure:

1. **Consistency** - All developers follow the same patterns and practices
2. **Quality** - Code meets established standards and best practices
3. **Maintainability** - Code is organized and documented properly
4. **Accessibility** - UI meets WCAG guidelines
5. **Security** - Proper security practices are followed

## When to Update Rules

Update these rules when:
- Adding new technologies or dependencies
- Establishing new design patterns
- Changing development workflows
- Adding new security requirements
- Updating accessibility standards

## Important Notes

- **style.md** is the single source of truth for all UI design decisions
- All rules should be followed unless there's a documented exception
- New patterns should extend existing systems, not replace them
- Accessibility and security are non-negotiable requirements
